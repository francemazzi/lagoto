# Avanzamento della build nativa — 5 ottobre 2026

**Milestone di sviluppo funzionante. I gate P00–P12 sono ancora aperti; nessuna beta pubblicata.** Questo report aggiorna il precedente inventario iniziale senza sostituire le evidenze storiche. La roadmap e gli identificativi dei requisiti restano invariati.

## Percorso provato

Nella UI SwiftUI: creazione e verifica di profili Codex/Claude, progetto con backend/frontend/desktop, task, tre worktree isolati, modifica del contratto, streaming con strumenti, cambio Codex → Claude con anteprima del contesto, riavvio, verifica esplicita con `node verify.mjs`, criterio collegato alla prova, revisione e tre commit locali. I cloni originali restano puliti a versione 1; i worktree sono puliti a versione 2. Il test del backend produce `CONTRACT_OK`; il task non viene completato dalla sola risposta del modello.

Separatamente, il coordinatore ha completato **10 turni e 9 handoff reali** nella stessa fixture a tre repository:

`Codex → Claude → Qwen/OpenRouter → Ollama → Kimi/OpenRouter → Cursor → Codex → Cursor → Claude → Cursor`

Dopo ogni turno, un controllo indipendente legge i tre file e verifica versione e marcatore; la conferma duplicata restituisce lo stesso successore. Il checkpoint finale viene ripristinato in repository Git indipendenti. La sequenza è proseguita dopo riavvii del coordinatore. Sono prove reali dei percorsi dichiarati, **non cinque sessioni personali complete** né l’intera matrice di crash durante handoff.

I primi tentativi restano registrati come falliti: Codex non copiava il file senza newline con il tool di modifica; Qwen ha applicato due incrementi; Kimi ha omesso il newline. La fixture ora esplicita terminatore e versione attesa, e il Context Pack distingue richieste storiche da richiesta corrente. Non sono garanzie universali di correttezza dei modelli. Un retry del runner ha inoltre incontrato una destinazione restore già esistente: corretto usando una nuova destinazione, senza sovrascrivere il recupero precedente.

Qwen e Kimi sono stati collaudati tramite la chiave OpenRouter di prova autorizzata, custodita nel Portachiavi. Il login Google delle console non viene reinterpretato come credenziale API. QwenCloud e Moonshot diretti restano non verificati.

Cursor non presenta le modifiche native Agent come operazioni sempre soggette a callback: può scrivere nei worktree concessi. Il wrapper macOS impedisce le scritture esterne, incluse quelle tramite processi figli e symlink nella fixture. Il rifiuto di un comando è verificato separatamente con una vera richiesta ACP. Le letture del CLI non sono globalmente confinate dal wrapper; non si dichiara una sandbox universale.

Il monitor dei processi osserva i gruppi registrati. Processi detached non osservabili o record storici senza identità durevole restano bloccanti, senza terminare PID sulla base del solo numero. Il restore di un backup non importa autorizzazioni a segnalare processi della macchina precedente.

## Verifiche della milestone

- Regressione: **63 test TypeScript e 6 test Swift**, senza skip nell’ultima esecuzione completa prima del report; le riesecuzioni finali sono registrate dal gate.
- Restore di tre repository: file, indice, staged/unstaged, binari, cancellazioni e symlink; recupero anche dopo rimozione dei cloni originali; corruzione rifiutata prima della creazione della destinazione.
- Consegna su tre remote Git locali reali: errore iniettato nel push del secondo, retry senza duplicare commit e senza perdere staging estraneo. La consegna applicativa verso GitHub resta da collaudare live; il precedente smoke GitHub prova strumenti e credenziali.
- Crash reale del processo coordinatore sintetico: il figlio resta vivo e viene arrestato tramite identità durevole; una simulazione di PID riusato non invia segnali e non dichiara lo stop riuscito.
- GitHub applicativo: due percorsi reali, da repository esistente e da cartella non Git, su repository sintetici privati. Anteprima → creazione → errore di trasporto iniettato nel push → restart → retry sullo stesso ID remoto, senza perdita dell’indice né dei file unstaged. Commit remoto e visibilità verificati con API GitHub indipendente. I repository di prova sono archiviati, privati e recuperabili. Questo prova il servizio applicativo, non i nuovi pannelli nativi ancora da collaudare.
- Inizializzazione Git: l’anteprima prepara un candidato nell’archivio Lagoto e lascia la cartella originale senza `.git`. La conferma installa solo i metadati del commit selezionato. Ignorati e nomi/contenuti sensibili riconosciuti sono esclusi; filtri personalizzati/LFS sono bloccati. Modifiche concorrenti e metadati sostituiti impediscono l’installazione; una copia parziale con prova di proprietà può riprendere senza sovrascrivere file estranei.
- Restore: le anteprime non concluse di pubblicazione, consegna e handoff vengono invalidate nel nuovo archivio; le verifiche passate diventano da ripetere. I test impediscono di riutilizzare le vecchie autorizzazioni sui percorsi originali.
- Budget: rinnovo manuale idempotente con prenotazioni precedenti trattenute, saldo del nuovo ciclo preservato quando arriva usage tardivo, deroga persistita con motivo e riserva protetta. Calibrazione esclusa per giorni parziali, inattivi o incerti. Questi test non coprono tutta la matrice BAT.
- Carico: 50 progetti, 1.000 task, 100.000 eventi; **p95 circa 0,24 ms** per lettura snapshot e codifica/decodifica JSON nel runtime. La misura esclude rendering SwiftUI e non chiude P12-I03.
- `pnpm gate all` resta **failed**, intenzionalmente: i test parziali sono elencati ma non promossi a copertura completa dei requisiti.

Mac: Apple Silicon Mac16,5, macOS 26.6.2, Xcode 27; Node 22.23.1, SDK Qwen 0.1.17, better-sqlite3 13.0.3. Versioni CLI e risultati sanitizzati nel [riepilogo](native-workflow-summary.json). Gli output completi locali sono in `build/evidence/`, esclusi da Git; le trascrizioni personali non sono pubblicate.
